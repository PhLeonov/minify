# Minify на iPhone, Android и в браузере

PWA использует общее с desktop-версией ядро `internal/compress`. Go компилируется в WebAssembly и сжимает фото в Web Worker на устройстве пользователя. Сервер обработки, аккаунт внутри приложения и загрузка фотографий в облако не нужны.

## Бесплатная публикация без GitHub

Готовый архив: **`build/minify-pwa.zip`**. Загружать нужно этот архив, а не всю папку проекта.

1. Войдите в свой аккаунт Cloudflare и откройте **Workers & Pages**.
2. Выберите создание проекта **Pages → Direct Upload / Upload assets** (названия пунктов могут меняться).
3. Задайте свободное имя проекта и загрузите `build/minify-pwa.zip`.
4. Опубликуйте проект. Cloudflare выдаст HTTPS-адрес вида `https://имя.pages.dev`.
5. Откройте адрес на iPhone в Safari. Дождитесь «Готово к работе офлайн».
6. Нажмите «Поделиться» → «На экран Домой». После установки один раз откройте приложение с интернетом и снова дождитесь готовности офлайн.

Компьютер можно выключить. Для обновления соберите новый архив и загрузите новую версию в тот же проект. Новая версия кеша активируется после закрытия всех окон Minify. Фотографии и результаты между перезапусками не сохраняются — сначала скачайте их или сохраните через меню «Поделиться».

Cloudflare Pages поддерживает загрузку ZIP: https://developers.cloudflare.com/pages/get-started/direct-upload/

Проект подготовлен к публикации, но сама локальная сборка **не создаёт публичный сайт** и не регистрирует аккаунт хостинга.

## Альтернатива: GitHub Pages

1. Разместите исходники в своём репозитории. На GitHub Free для Pages нужен публичный репозиторий; не добавляйте туда личные фото и секреты.
2. Откройте **Settings → Pages → Source → GitHub Actions**.
3. В **Actions → Publish Minify PWA → Run workflow** запустите сборку.
4. Адрес появится в результате задания. Относительные пути поддерживают адрес вида `https://user.github.io/minify/`.

Workflow запускается только вручную. Он публикует `build/web`, а не исходники Go, desktop-бинарник или тесты. Настройка хостинга/репозитория выполняется владельцем аккаунта.

## Локальная сборка

Нужны Go 1.25+ и Node.js 22+. Для сборки сайта сторонние npm-пакеты не нужны.

```powershell
go test ./...
node scripts/build-web.cjs
node scripts/serve-web.cjs
```

Откройте `http://localhost:4179`. Готовый сайт — в `build/web`, архив — `build/minify-pwa.zip`. Для хостинга достаточно содержимого этой папки. Сборка автоматически берёт `wasm_exec.js` от используемого компилятора и обновляет версию офлайн-кеша.

`file://` и обычный HTTP по локальному IP не подходят для установки и офлайн-режима. Для телефона нужен HTTPS. Для работы установленного приложения офлайн браузер должен сохранить кеш; iOS может удалить его при нехватке места.

## Как пользоваться

Выберите JPEG/PNG, настройте качество и нажмите «Сжать фотографии». У каждого результата есть «Скачать», а при поддержке браузером обмена файлами — «Поделиться / сохранить». На iPhone системное меню позволяет сохранить в «Фото» или «Файлы». При пакетной обработке доступно общее меню сохранения, если браузер поддерживает выбранный набор файлов.

Приложение создаёт копии и не удаляет оригиналы. Показанная экономия — разница размеров копий и исходников, **не уже освобождённая память телефона**. Для экономии места пользователь сам решает, какие оригиналы удалить после проверки копий.

Ограничения мобильной версии: JPEG/PNG, до 24 Мп и 64 МБ на файл, до 40 файлов и 128 МБ на очередь. HEIC/HEIF, Live Photos и анимированный PNG не поддерживаются. Если галерея выдаёт HEIC, сначала экспортируйте JPEG. Метаданные и ICC-профили при перекодировании не сохраняются. Если кодирование не уменьшает файл, возвращаются исходные байты, формат и размеры. Держите приложение открытым во время обработки: iOS может приостанавливать фоновые страницы.

## Где читать код

- `internal/compress/compress.go`: общее ядро `Encode` и файловая обёртка `Process`.
- `cmd/wasm/main.go`: передача байтов между JavaScript и Go, лимиты мобильной памяти.
- `web/worker.js`: загрузка Go и обработка одного фото вне основного потока.
- `web/app.js`: очередь, отмена, скачивание, системное меню сохранения и установка.
- `web/sw.js`: кеш только файлов приложения, без фотографий.
- `scripts/build-web.cjs`: сборка WASM, иконок, версии кеша и архива хостинга.

Приложение не использует внешние шрифты, CDN-скрипты или аналитику. При первой загрузке хостинг получает обычные запросы файлов сайта; байты выбранных фотографий не передаются по сети.

## Проверки

```powershell
go test ./...
go vet ./...
npm.cmd ci
npx.cmd playwright install webkit
npm.cmd run test:web
```

В Windows тесты Chromium используют установленный Microsoft Edge. На других платформах установите также `npx playwright install chromium`. В macOS/Linux используйте `npm`/`npx` без `.cmd`.

Браузерные тесты проверяют реальное Go/WASM-сжатие, скачивание, отмену, прозрачность, работу в подпапке сайта и обработку после перезагрузки без сети. WebKit на компьютере не заменяет окончательную проверку установки и системного меню сохранения на настоящем iPhone.
